# Luqyak — release-readiness audit (2026-11-14)

## Scope and safeguards
- Target: `luqyak.athat.app`, Cloudflare Worker `luqyak`, repository `Luqyak`.
- No production D1 migrations, deletions, R2 writes, or fabricated user accounts were performed during this audit.
- Automated public-route regression checks: `npm run validate` (syntax and `tests/*.test.mjs`). GitHub workflow: `.github/workflows/quality-gates.yml`.
- A successful Worker upload is a **syntax validation** only; it does not prove that push notifications arrive on actual devices or that end-to-end encryption is correctly implemented.

## Blocking security questions before a public security claim
1. The `/api/chat/messages` path reads message `body` values from `lk_account_messages` in D1. Confirm whether bodies are ciphertext or plaintext, and whether the account-chat client encrypts **before** sending. Do **not** state that every chat is end-to-end encrypted until this is proved.
2. The separate `/api/private/*` paths contain cryptographic handling; they require an independent multi-device key continuity review.
3. Test unauthorized photo requests, member removal, invitation decline, account logout, and account deletion with dedicated test users.
4. Define and publish a backup/recovery contract. Local-only encryption and effortless device recovery cannot both be promised without a key-recovery design.

## Two-account device acceptance matrix
Use *two dedicated consenting test accounts* and two devices, one iPhone (installed PWA) and one Android (installed PWA). No existing personal accounts.
1. Register/verify/login both accounts; log out and back in; verify sessions do not leak to one another.
2. Send/accept/reject friend requests; confirm blocked users cannot message or view private albums.
3. Send messages A→B and B→A; check ordering, read receipts, reconnect behavior, notification taps, and cross-device continuity.
4. Send a meetup invitation; verify navigation to the correct meetup, RSVP update, maps selection and calendar reminder.
5. Photograph from each device, upload multiple photos, reopen full-screen viewer, swipe, download, comment, and test access after revocation.
6. Disable the network during an upload; re-enable it; verify a single delivered copy and no lost drafts.
7. Lock and close both apps; test push notification arrival separately on iOS and Android with permission enabled/disabled.
8. Switch device for one test account. Verify what can be recovered with and without the original device, without implying unimplemented cloud backups.

## Performance gates
- Cold and repeat launch, memory album scrolling, message send/receive, photo uploads under 4G/slow connection.
- Measure p50/p95 times rather than inventing scores; no current measured latency baseline.
- Test phone (narrow portrait), tablet (portrait/landscape), and desktop (wide), including back navigation and safe areas.

## App Store preparation
- A signed iOS app and TestFlight build require an Apple Developer account, macOS/Xcode and signing; not generated by the Cloudflare Worker alone.
- Apple requires user-generated content safeguards: filtering, reporting, blocking and published contact details (App Review Guideline 1.2).
- Provide in-app and Store privacy policy, retention/deletion descriptions, camera/photos/notifications permission copy, account deletion, age-rating answers, screenshots, icons, support URL and reviewer access.
- Verify current Xcode/SDK submission requirements immediately before upload.
- Do not submit placeholder screenshots or claim tests have passed without device evidence.

## Verified follow-up (source and mock Worker checks, 2026-11-14)
- The existing account-chat endpoint `/api/chat/send` accepts a plaintext `text` value and inserts its `body` into `lk_account_messages` in D1. This is **not end-to-end encryption**. The account-chat UI now discloses this limitation and points to the separate private chat. Existing message data was not modified. A proper migration requires a reviewed key-management and multi-device recovery design.
- The main `/app` HTML response now sends `Cache-Control: no-store`, consistent with its privacy regression test.
- A JavaScript/V8 mock invocation of the Worker successfully compiled its source and returned HTTP 200 for `/manifest.webmanifest`, `/luqyak-sw.js`, `/app`, and `/account-chat`.
- Seven unauthenticated GET/POST requests to image, profile, public-account-chat and private-chat API routes returned HTTP 401 with `no-store` cache directives under mock execution, without DB/R2 access or writes.
- The new tests include explicit assertions for the plaintext-chat disclosure, private image permission checks, send deduplication and per-minute rate limit. These are regression tests, **not** a full cryptographic audit.
- GitHub Actions test-run results have not yet been independently confirmed. Mock-worker checks are not a substitute for `npm run validate` under Node or for integration tests.
- No physical iPhone or Android tests, account registrations, media uploads, D1 mutations, message deliveries, or restored-device checks were performed.

## Release rule
**Do not declare fully tested, secure, or App Store-ready** until the above two-account/device matrix and the cryptography/security checks are complete. Minor UI updates can deploy independently once automated checks pass.
