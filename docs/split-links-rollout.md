# لُقياك — رابط التصوير ورابط المشاهدة (مرحلة آمنة)

## ما نُفذ على فرع التطوير

يدعم `guestOwnerHandler` الآن خيار `link_set: "split"` عند إنشاء رابط من صاحب اللقاء، ويعيد:
- `capture_url`: رابط يسمح للضيف الموافق عليه **برفع الصور فقط** (`can_upload=1`, `can_view=0`).
- `view_url`: رابط يسمح للضيف الموافق عليه **بمشاهدة الصور المعتمدة فقط** (`can_upload=0`, `can_view=1`).
- `url`: مرجع متوافق مع الواجهات القديمة ويساوي `capture_url` عند الطلب الجديد.

الروابط عشوائية مستقلة، ولا تُحفظ قيمها الخام في قاعدة البيانات، بل بصمة SHA-256. ينشأ الرابطان دفعة واحدة عبر D1 batch. لا تُغيّر الجداول القديمة أو صلاحيات الروابط السابقة.

## الربط المطلوب بالواجهة

يرسل حساب صاحب اللقاء الطلب الموجود في المسار الحالي لإنشاء رابط الضيف، ويضيف `link_set: "split"`. ثم يعرض زرين منفصلين: «نسخ رابط التصوير» و«نسخ رابط المشاهدة». يجب عدم إظهار الرابط الثاني ضمن رسالة دعوة التصوير تلقائيًا. تم ربطها بواجهة صاحب اللقاء على فرع التطوير: نافذة المشاركة تعرض رابط التصوير ورابط المشاهدة وزرَي النسخ والمشاركة لكل واحد. لم تُنشر على الإنتاج بعد.

## شروط أمنية قبل الإطلاق

1. اختبار مستخدمين مستقلين: حامل رابط التصوير لا يستطيع استعراض الصور أو تنزيلها، وحامل رابط المشاهدة لا يستطيع الرفع، حتى عبر استدعاء API مباشرة.
2. يظل رابط التصوير صالحًا للرفع ما دام اللقاء غير منتهٍ، وينبغي فرض تاريخ انتهاء مستقل على مستوى الرابط إذا جرى تفعيل المدة القابلة للتمديد؛ ذلك **لم يُنفذ بعد**.
3. الحالة الحالية تُخزن الصور في R2 وتعرضها عبر Worker؛ لا يجوز وصفها بأنها «وسيط مشفر مؤقت لا يحتفظ بالصور» أو «تخزين محلي حصري».
4. تنفيذ بروتوكول تشفير بين الطرفين قبل رفع الصور، مع ضمان نقلها وتأكيد الحفظ على جهاز المنشئ ثم تنظيف النسخة المؤقتة في الوسيط؛ يتطلب تصميم آلية وصول عند انقطاع جهاز المنشئ.
5. ملف PDF يحتاج مولّدًا عميلًا آمنًا، مع منع كشف الصور الخاصة عبر روابط عامة.
6. لا حذف للصور القديمة ولا تغيير للمخططات قبل ترحيل مُختبر ونسخة احتياطية.

## اختبار الإصدار

`npm run validate` + اختبارات مستخدمين حقيقيين بأجهزة منفصلة + مراجعة GitHub Actions. عدم الدمج أو النشر عند فشل الاختبارات.
